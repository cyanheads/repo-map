# 0.15.0 — 2026-11-13

## Added

- **`--dry-run`** prints the upload summary and one `<bytes>\t<path>` line per file the run would send, then exits. It sends nothing, writes nothing to the target, and needs no API key ([#34](https://github.com/cyanheads/repo-map/issues/34)).
- **Strict structured output**: when one of the model's endpoints supports structured outputs, requests carry a strict JSON schema (`file_analysis`) instead of `json_object`. The capability check is one keyless endpoints lookup per run, made after consent; a failed lookup falls back to `json_object` with one warning ([#36](https://github.com/cyanheads/repo-map/issues/36)).
- **Language mappings** for Makefile, `.mjs`/`.cjs`, `.mts`/`.cts`, `.c`, `.rs`, and `.toml`; `.mjs` and `.mts` files also get import extraction ([#30](https://github.com/cyanheads/repo-map/issues/30)).
- **Nested ignore rules**: every `.gitignore` the walk reaches and `.git/info/exclude` apply, parsed in-process with `pathspec`. Inside a larger Git work tree, the `.gitignore` files from its top down to the target apply too. The scanner never runs `git`, and the global excludes file is not read ([#35](https://github.com/cyanheads/repo-map/issues/35)).
- **Enclosing-tree warning** when the target itself is ignored by its enclosing work tree.

## Changed

- **Consent prompt** runs after the scan and states this run's file count, source KiB, model, and the number of files that keep a cached analysis. One scan feeds both the prompt and the analysis pass, and nothing is written to the target before consent ([#34](https://github.com/cyanheads/repo-map/issues/34)).
- **Exit status** is 0 only when every pending file was analyzed and the report was written. A partial run still writes the report and exits 1, as does a run stopped by a fatal OpenRouter error. Ctrl-C exits 130 ([#33](https://github.com/cyanheads/repo-map/issues/33)).
- **OpenRouter errors** are classified per response: fail the file, retry, or end the run. Invalid key, exhausted credit, and an unknown or rejected model end the run; a timeout is now retried, and `Retry-After` is honored ([#33](https://github.com/cyanheads/repo-map/issues/33)).
- **`critical_dependencies`** is sent as an array of `{"name", "reason"}` objects on the wire for every model. The stored cache and report format are unchanged ([#36](https://github.com/cyanheads/repo-map/issues/36)).
- **Default exclusions** replace `.env` and `.envrc` with `*.env` and `*.envrc`, and add `*.tfvars.json`, `*.tfstate.*`, `*secrets.toml`, and `credentials.toml` ([#32](https://github.com/cyanheads/repo-map/issues/32), [#30](https://github.com/cyanheads/repo-map/issues/30)).
- `ANALYSIS_CONTRACT_VERSION` 2 → 3, so every cached analysis is reanalyzed once.

## Fixed

- **Report write failure** no longer logs a "saved" line after an `OSError`; the run logs one error and exits 1 ([#33](https://github.com/cyanheads/repo-map/issues/33)).
- **Invalid ignore rules**: non-UTF-8 bytes or an unparseable line in a `.gitignore` no longer abort the scan; the bad line is dropped with a warning ([#35](https://github.com/cyanheads/repo-map/issues/35)).

## Security

- **PEM private-key check**: a file whose content contains a PEM private-key header is never sent, never cached, and skipped with a warning naming it. The check reads content, so no ignore rule can override it ([#29](https://github.com/cyanheads/repo-map/issues/29)).
- **Credential exclusions** now cover prefixed names such as `prod.env`, `local.envrc`, `terraform.tfstate.backup`, and `terraform.tfvars.json` ([#32](https://github.com/cyanheads/repo-map/issues/32)).
- **Nested ignore rules** keep files listed in a subdirectory `.gitignore` or `.git/info/exclude` out of the upload ([#35](https://github.com/cyanheads/repo-map/issues/35)).
